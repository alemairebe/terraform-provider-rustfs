# rustfs_ilm_transition Resource

Starts a manual ILM transition run for one bucket (optionally narrowed to a prefix) and keeps the durable job the server returns.

### This resource moves data

A transition copies or moves objects to the named storage tier. A wrong `bucket` or `prefix` can move far more data than intended, and moving it back is not a provider operation. `dry_run` reports what would be enqueued without moving anything; run it first against an unfamiliar lifecycle configuration.

### Lifecycle

`Create` starts the run in the server's durable-job mode and records `job_id`; `Read` reports the job's current `state` and progress counters. Every configurable attribute carries `RequiresReplace`, so changing one starts a **new** run instead of editing the finished one. `triggers` exists only to re-run a transition with the same parameters.

`Delete` is a **no-op**: the provider never cancels a run, never rolls a transition back and never mutates ILM state on destroy. `terraform destroy` only forgets the record. Cancel a run with the admin API (`DELETE /rustfs/admin/v3/ilm/transition/jobs/{job_id}`) if that is what you want.

### Missing jobs

The server answers `NoSuchKey` once it no longer holds the job record; at that point `Read` removes this resource from state without error.

### Requirements

The caller needs the `SetTierAction` admin action for the run. The routes ship from RustFS 1.0.1 on; an older server fails with a diagnostic naming the route and its version.

## Example Usage

```terraform
# A transition moves objects to a tier. Try the parameters with dry_run first:
# it reports what would be enqueued without moving anything.
resource "rustfs_ilm_transition" "logs_to_warm" {
  bucket  = "logs"
  prefix  = "archive/"
  tier    = "WARM"
  dry_run = true

  # Changing a trigger starts a new run with the same parameters.
  triggers = {
    run = "2026-10-20"
  }
}

output "transition_job_id" {
  value = rustfs_ilm_transition.logs_to_warm.job_id
}

# Read the job back through terraform refresh; `terraform destroy` only forgets
# this record. It never cancels the run or rolls the transition back.
```

## Schema

### Required

- `bucket` (String) Bucket whose objects are transitioned. There is no default: a transition must name its bucket explicitly. Changing it starts a new run.

### Optional

- `dry_run` (Boolean) Report what would be enqueued without moving any object. Changing it starts a new run.
- `max_duration_seconds` (Number) Maximum wall-clock seconds this run may take. `0` leaves the budget to the server; the server accepts at most 3600. Changing it starts a new run.
- `max_objects` (Number) Maximum number of objects this run scans. `0` uses the server default (10000); the server accepts at most 100000. Changing it starts a new run.
- `prefix` (String) Object key prefix to narrow the run. The empty default covers the whole bucket. Changing it starts a new run.
- `tier` (String) Storage tier to transition to, matched case-insensitively by the server. Empty selects the target from the bucket's lifecycle configuration. Changing it starts a new run.
- `triggers` (Map of String) Arbitrary values that are not sent to the server. Change one to start a new run with the same parameters, for example to re-run a nightly transition.

### Read-Only

- `cancel_endpoint` (String) Admin route that cancels this job. The provider never calls it.
- `cancel_requested` (Boolean) Whether a cancellation has been requested on this job out of band.
- `completed_at_unix_nanos` (Number) Job completion time in Unix nanoseconds; null while the job is still running.
- `created_at_unix_nanos` (Number) Job creation time in Unix nanoseconds, as reported by the server.
- `failure_reason` (String) Why the job failed, when the server reports one.
- `id` (String) Durable job id of the transition run.
- `job_id` (String) Durable job id of the transition run; equal to `id`.
- `queue_snapshot` (Attributes) Transition worker queue pressure recorded with the job. (see [below for nested schema](#nestedatt--queue_snapshot))
- `report` (Attributes) Scan and enqueue counters of the run. (see [below for nested schema](#nestedatt--report))
- `state` (String) Job state reported by the server: `accepted` right after the run, then `running`, `completed`, `partial`, `failed`, `cancelled` or `unknown`.
- `status_endpoint` (String) Admin route that reports this job.
- `updated_at_unix_nanos` (Number) Last job update time in Unix nanoseconds, as reported by the server.
