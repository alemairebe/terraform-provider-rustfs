# rustfs_kms_rekey Resource

Start a RustFS bulk rekey sweep over one or more buckets or prefixes.

Rekey re-wraps the stored data-key envelopes under the current key-encryption key. It does not rewrite object bodies, does not change ETags or object versions, and never destroys a superseded key version: objects that were already re-wrapped stay readable while the sweep runs and after it is cancelled.

Creating this resource starts the sweep and returns once the server accepts it. Refreshing reads the current or most recent sweep, so `state`, `current_bucket` and the counters update while it runs. Destroying a running sweep requests cancellation; the cancel is cooperative and does not move already re-wrapped envelopes back. A completed sweep is left alone.

RustFS answers `501` when the configured KMS backend cannot re-wrap envelopes: Local, Static and AWS cannot, while Vault KV2 and Vault Transit can. A second sweep is refused while one is running.

Import takes the server's job id. The configured `buckets` and `prefix` are not recoverable from the server, so set them in configuration after importing.

## Example Usage

```terraform
# Re-wrap the data-key envelopes of one bucket under the current KEK.
# Destroying a running sweep only requests cancellation; already re-wrapped
# objects stay re-wrapped. Local, Static and AWS backends answer 501.
resource "rustfs_kms_rekey" "photos" {
  buckets = ["photos"]
  prefix  = "originals/"
}
```

## Schema

### Optional

- `buckets` (List of String) Buckets to sweep. Omit or leave empty to sweep every bucket. Changing this starts a new sweep.
- `prefix` (String) Object-key prefix to restrict the sweep to. Changing this starts a new sweep.

### Read-Only

- `already_current` (Number) Envelopes already on the current key version.
- `current_bucket` (String) Bucket currently being walked, empty when the sweep is between buckets or finished.
- `failed` (Number) Versions whose re-wrap or metadata write failed. A re-run retries them.
- `id` (String) Terraform resource ID; the server's job id.
- `job_id` (String) Server-generated id of the sweep.
- `not_applicable` (Number) Versions with nothing to re-wrap (plaintext, SSE-C or MinIO-sealed).
- `rewrapped` (Number) Envelopes re-wrapped and persisted.
- `scanned` (Number) Object versions the walk has yielded.
- `state` (String) Sweep state: `running`, `completed` or `cancelled`.
