# rustfs_scanner_usage_state_reset Resource

Run the scanner usage-state rebuild (POST /rustfs/admin/v3/scanner/usage-state/reset). This is destructive to accounting: the reset discards the durable usage baseline and publishes a bootstrap-pending marker, and the next complete scanner cycle rebuilds usage from a full pass. Bucket quotas and usage reporting may briefly misreport while that happens. The action is one-shot: Read only echoes the recorded result, Delete is a no-op, and changing `triggers` runs it again. The route is synchronous; the provider retries a busy scanner leader lock a few times and then fails, so retry the apply after the current cycle ends if the lock stays busy. Scanner tuning stays in the `scanner` subsystem of `rustfs_config` or in the server environment.

## Example Usage

```terraform
# Destructive scanner usage-state rebuild. The reset discards the durable usage
# baseline and leaves a bootstrap-pending marker; the next complete scanner
# cycle rebuilds usage from a full pass. Bucket quotas and usage reporting may
# briefly misreport while that happens, so confirm_full_rebuild is required.
#
# The resource is an action, not managed state: Read only echoes the result and
# Delete is a no-op. Change a trigger when you deliberately want to run it again.
resource "rustfs_scanner_usage_state_reset" "rebuild" {
  confirm_full_rebuild = true

  triggers = {
    reason = "persisted-usage-floor-conflict"
  }
}

output "scanner_usage_reset" {
  value = {
    usage_state  = rustfs_scanner_usage_state_reset.rebuild.usage_state
    leader_epoch = rustfs_scanner_usage_state_reset.rebuild.leader_epoch
    next_cycle   = rustfs_scanner_usage_state_reset.rebuild.next_cycle
  }
}
```

## Schema

### Required

- `confirm_full_rebuild` (Boolean) Must be `true`. Acknowledges that the reset discards the durable usage baseline, that quotas and usage reporting can misreport until the rebuild completes, and that the scanner must run a full pass to recover it.

### Optional

- `triggers` (Map of String) Arbitrary values that are not sent to the server. Change one to run the reset again; without a change Terraform does not repeat it.

### Read-Only

- `id` (String) Reset trigger identifier.
- `leader_epoch` (Number) Storage publication epoch the reset was fenced with.
- `mode` (String) Reset mode the server applied, `full-rebuild`.
- `next_cycle` (Number) Scanner cycle that will perform the rebuild.
- `reset_paths` (List of String) Usage objects the reset cleared or marked.
- `status` (String) Status the server returned for the reset.
- `usage_state` (String) Usage state the reset left behind, normally `bootstrap-pending`.
