# rustfs_bucket_recovery Resource

Recover an orphaned bucket: bucket metadata (or its incarnation sidecar) that survived after the bucket's volume directories were removed outside RustFS, leaving an ordinary `CreateBucket` to refuse the name.

The operation is **generation-fenced**. `incarnation_id` is the exact incarnation UUID the orphaned metadata belongs to, sent as `expectedIncarnationId`; RustFS refuses the recovery when a disk still holds the volume, when any disk is offline or its metadata is unreadable, or when the identity does not match. That UUID, not the bucket name, is what makes the operation safe, so it is also the resource `id`: bucket names are reusable, and a recovery pinned only to a name could refer to a later, unrelated bucket.

### Usage

Recovery retires the orphan and frees the name; it does not create a bucket. Pair it with a `rustfs_bucket` for the same name whose `depends_on` lists this resource, as in the example below. Used alone, the next refresh finds no bucket (`Read` can only confirm existence), removes this resource from state, and Terraform plans the recovery again. Because the server retires the input UUID, re-sending the request is safe, but the plan never converges.

### Where the UUID comes from

The UUID is not generated by Terraform. Read it from the orphaned bucket's incarnation sidecar, or from a trusted metadata backup taken from that bucket. A diagnostic metadata export is **not** a restorable backup and does not carry a usable identity.

### Read and destroy

There is no route to read orphan state back: once the name is recreated the bucket is ordinary, so `Read` can only confirm that the bucket exists. A missing bucket is removed from state without error; an existing one keeps its state as the audit trail. Because the server retires the input UUID and a recreated bucket receives a new generation whose UUID this route does not return, the provider cannot later prove that the live bucket is the one it recovered.

`Delete` is a **no-op**. Recovery cannot be undone, and the provider never deletes the recovered bucket or its objects: `terraform destroy` only forgets the record. Remove the bucket itself with `rustfs_bucket` if that is what you want.

### Restrictions

Recovery is local to one deployment and is refused with `OperationAborted` while site replication is enabled; reconcile every site before retrying. The caller needs the `RecoverOrphanedBucketAction` admin action. The route ships in RustFS 1.0.2; on 1.0.1 the failure names the route and the server version.

## Example Usage

```terraform
# The incarnation UUID is not generated by Terraform: read it from the orphaned
# bucket's incarnation sidecar, or from a trusted metadata backup of that bucket.
# A diagnostic metadata export is not a restorable backup.
resource "rustfs_bucket_recovery" "orphaned_data" {
  bucket         = "orphaned-data"
  incarnation_id = "4f8c1f3e-9a2b-4c7d-8e10-2b6d5f0a1c33"
}

# Recovery frees the name but does not create a bucket. Recreate it here, after
# the recovery has retired the orphan metadata.
resource "rustfs_bucket" "orphaned_data" {
  name       = rustfs_bucket_recovery.orphaned_data.bucket
  depends_on = [rustfs_bucket_recovery.orphaned_data]
}

output "retired_incarnation_id" {
  value = rustfs_bucket_recovery.orphaned_data.retired_incarnation_id
}
```

## Schema

### Required

- `bucket` (String) Name of the orphaned bucket. It is only the request path parameter; the incarnation UUID is the resource identity. Changing it forces a new recovery.
- `incarnation_id` (String) Incarnation UUID of the orphaned bucket generation, sent as `expectedIncarnationId`. RustFS refuses the recovery unless every disk reports the bucket volume absent and reports this generation. Changing it forces a new recovery.

### Read-Only

- `id` (String) Incarnation UUID this recovery was fenced with.
- `retired_incarnation_id` (String) Incarnation UUID the server retired, as returned by the recovery response. The bucket is recreated later with a new generation, whose UUID this route does not return.
