# rustfs_object_data_cache_flush Resource

Flush the RustFS object data cache (POST /rustfs/admin/v3/object-data-cache/flush). Without `bucket` the whole cache is flushed; with `bucket` only that bucket; with `bucket` and `object` only that identity. The action is one-shot: Read only echoes the recorded result, Delete is a no-op, and changing `triggers`, `bucket` or `object` runs the flush again. Cache tuning stays in the server configuration.

## Example Usage

```terraform
# Drop cached object bodies. Omit bucket to flush the whole cache, set bucket to
# flush one bucket, or set bucket and object to flush one identity (the
# remediation for a poisoned entry short of a node restart).
#
# The resource is an action, not managed state: Read only echoes the result and
# Delete is a no-op. Change triggers, bucket or object to flush again.
resource "rustfs_object_data_cache_flush" "poisoned_object" {
  bucket = "logs"
  object = "2026/10/19/a.log"

  triggers = {
    reason = "poisoned-entry"
  }
}

output "object_data_cache_flush" {
  value = {
    scope        = rustfs_object_data_cache_flush.poisoned_object.scope
    outcome      = rustfs_object_data_cache_flush.poisoned_object.outcome
    removed_keys = rustfs_object_data_cache_flush.poisoned_object.removed_keys
  }
}
```

## Schema

### Optional

- `bucket` (String) Bucket whose cached objects are flushed. Omit to flush the whole cache.
- `object` (String) Object identity to flush. Requires `bucket`.
- `triggers` (Map of String) Arbitrary values that are not sent to the server. Change one to run the flush again; without a change Terraform does not repeat it.

### Read-Only

- `id` (String) Flush trigger identifier.
- `outcome` (String) Outcome the server reported: `removed` when entries were dropped, `noop` otherwise.
- `removed_keys` (Number) Number of cache entries the flush removed.
- `scope` (String) Scope the server applied: `all`, `bucket` or `object`.
