# rustfs_pool_decommission Resource

Drain and retire a RustFS storage pool.

**This resource moves data.** Creating it starts a decommission: RustFS copies every object of the named pool to the remaining pools and then retires the pool. Retiring the pool from the deployment still requires removing its volume expression from the server configuration and restarting RustFS; this resource only drives the drain and reports its progress.

The deployment must have at least two storage pools; RustFS answers `501 NotImplemented` on a single-pool deployment. The drain needs enough free space on the remaining pools for the drained data plus overhead, and a decommission cannot run while a rebalance is in progress.

Destroying an in-flight drain cancels it and clears the canceled record. Canceling does not move already relocated objects back, and a completed drain cannot be canceled or cleared: destroy leaves the completed record in place.

## Example Usage

```terraform
# Drain and retire one storage pool.
#
# The confirmation interlock has to repeat the pool command line because
# creating this resource moves every object of the pool to the remaining pools.
# Pick a pool from the rustfs_pools data source and remove its volume
# expression from RUSTFS_VOLUMES after the drain reports complete.
data "rustfs_pools" "all" {}

resource "rustfs_pool_decommission" "retire" {
  pool    = data.rustfs_pools.all.names[0]
  confirm = data.rustfs_pools.all.names[0]
}
```

## Schema

### Required

- `confirm` (String) Safety interlock: must repeat `pool` exactly. Starting a decommission moves data off the pool, so the target has to be named twice.
- `pool` (String) Command line of the storage pool to drain, exactly as `data.rustfs_pools.names` reports it (for example `/data{1...4}`).

### Read-Only

- `bucket` (String) Bucket the drain is currently working on.
- `bytes_decommissioned` (Number) Number of bytes drained successfully.
- `bytes_decommissioned_failed` (Number) Number of bytes that failed to drain.
- `canceled` (Boolean) Whether the drain was canceled.
- `complete` (Boolean) Whether the drain finished successfully.
- `current_size` (Number) Current free bytes on the pool.
- `decommissioned_buckets` (List of String) Buckets already drained from the pool.
- `failed` (Boolean) Whether the drain failed.
- `id` (String) Terraform resource ID; the pool command line.
- `object` (String) Object the drain is currently moving.
- `objects_decommissioned` (Number) Number of objects drained successfully.
- `objects_decommissioned_failed` (Number) Number of objects that failed to drain.
- `pool_status` (String) Pool lifecycle status reported alongside the drain, for example `active`, `decommissioning`, `decommissioned` or `blocked`.
- `prefix` (String) Object prefix the drain is currently working on.
- `queued` (Boolean) Whether the drain is queued behind another pool operation.
- `queued_buckets` (List of String) Buckets still waiting to be drained.
- `stage` (String) Current drain stage reported by the server.
- `start_size` (Number) Free bytes on the pool when the drain started.
- `started_at` (String) Start time of the drain as reported by the server, in RFC 3339. Null after a canceled drain.
- `status` (String) Decommission status reported by the server: `none`, `running`, `complete`, `failed` or `canceled`.
- `total_size` (Number) Total size of the pool in bytes.
- `waiting_reason` (String) Why the drain is waiting, when the server reports a reason.
