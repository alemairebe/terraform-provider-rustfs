# rustfs_bucket_on_demand_migration Resource

Attach an external S3-compatible **source bucket** to a local RustFS bucket and pull objects lazily on first read (`PUT`/`GET`/`DELETE /rustfs/admin/v3/on-demand-migration/{bucket}`).

### Create probes the source

Every create and update first sends the configuration with `?dry-run=true`: RustFS validates the configuration, probes the source (`HeadBucket` plus a one-key listing) and writes nothing. Only after that succeeds does the provider save the configuration, so an unreachable source or a wrong key never reaches bucket metadata.

### Secrets

The configuration read is redacted: `secret_key`, `session_token`, the Azure `account_key`/`sas_token` and the GCS service-account JSON come back as `REDACTED`. The provider keeps the configured values in state while the server reports them redacted, so a refresh produces no diff.

### Prerequisites

The `RUSTFS_ON_DEMAND_MIGRATION_ENABLED` module switch must be on on every node, and the deployment needs a RustFS license that covers on-demand migration. A `gcs_native` source additionally needs a server built with the `gcs` feature. The admin routes exist in every supported release (1.0.1+).

Write-back needs namespace locking enabled and exactly one pool with one erasure set. Other topologies can still read through the source, but a pull is refused as `unsupported`; the provider does not retry it.

### Destroy

`Delete` clears the configuration idempotently. Already-pulled objects stay in the bucket. Backfill is **not** managed by this resource: `POST /rustfs/admin/v3/on-demand-migration/{bucket}/backfill?op=start|cancel` is a job whose `completed_with_failures` state has no Terraform equivalent.

## Example Usage

```terraform
# On-demand migration requires the RUSTFS_ON_DEMAND_MIGRATION_ENABLED module
# switch on every node and a RustFS license that covers the feature. Creating or
# updating the resource probes the source with ?dry-run=true first, so an
# unreachable endpoint or a wrong key fails before anything is persisted.
resource "rustfs_bucket" "photos" {
  name = "photos"
}

resource "rustfs_bucket_on_demand_migration" "photos" {
  bucket = rustfs_bucket.photos.name

  source = {
    provider = "minio"
    endpoint = "https://legacy.example.com:9000"
    region   = "us-east-1"
    bucket   = "legacy-photos"

    credentials = {
      access_key = var.source_access_key
      secret_key = var.source_secret_key
    }
  }

  filter = {
    source_prefix = "photos/"
  }

  policy = {
    inline_max_bytes     = 16777216
    max_concurrent_pulls = 8
  }
}

variable "source_access_key" {
  type = string
}

variable "source_secret_key" {
  type      = string
  sensitive = true
}

output "on_demand_migration_updated_at" {
  value = rustfs_bucket_on_demand_migration.photos.updated_at
}
```
