# rustfs_replication_diff Data Source

Reads the object versions of a bucket whose replication is still pending or has failed. RustFS computes the diff on demand by scanning object versions, bounded to 10,000 versions per call; `is_truncated` reports that the scan stopped early, so re-run with a narrower `prefix`. The bucket needs a replication configuration. This data source is read-only: it never retries, resyncs or mutates replication state. The counters are read from the aggregate response shape, a RustFS extension that reports scan coverage; the madmin-compatible stream has no envelope to carry it.

## Example Usage

```terraform
data "rustfs_replication_diff" "photos" {
  bucket = "my-bucket"
  prefix = "photos/"
}

output "unreplicated_versions" {
  value = data.rustfs_replication_diff.photos.entries
}

output "diff_scan_truncated" {
  value = data.rustfs_replication_diff.photos.is_truncated
}
```

## Schema

### Required

- `bucket` (String) Bucket whose replication diff to read.

### Optional

- `prefix` (String) Only scan object versions under this prefix. Narrowing the prefix also narrows the 10,000-version scan limit.

### Read-Only

- `entries` (Attributes List) Object versions with a pending or failed replication status. (see [below for nested schema](#nestedatt--entries))
- `id` (String) Data source identifier, derived from the query.
- `is_truncated` (Boolean) Whether the on-demand scan hit its 10,000-version limit before reaching the end of the prefix, so `entries` is partial.
- `json` (String) Raw JSON aggregate response as returned by the RustFS admin API.
- `replication_configured` (Boolean) Whether the bucket has a replication configuration. When false the diff is empty and no scan was run; the server reports ReplicationConfigurationNotFoundError.
- `scanned_versions` (Number) Number of object versions the server scanned for this diff.
