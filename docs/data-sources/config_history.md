# rustfs_config_history Data Source

Read the config snapshots RustFS stores before every configuration mutation (GET /rustfs/admin/v3/list-config-history-kv). RustFS saves the whole server configuration, not a per-subsystem diff, so every entry describes the same scopes; there is no per-subsystem filter and the route records no actor. `data` is the snapshot in the same directive text as `get-config-kv` with secret-like values replaced by the server (`data_redacted`), and it is marked sensitive because the snapshot can still hold values the server does not classify as secrets. Pass `restore_id` to `rustfs_config_restore` to roll back to an entry.

## Example Usage

```terraform
# RustFS saves the whole server configuration before every mutation. Entries
# carry no actor, and `data` is the snapshot with secret-like values redacted.
# The server returns them oldest first.
data "rustfs_config_history" "recent" {
  max_entries = 20
}

output "config_restore_ids" {
  value = [for entry in data.rustfs_config_history.recent.entries : entry.restore_id]
}
```

## Schema

### Optional

- `max_entries` (Number) Maximum number of newest entries to return. The server requires this value; the data source defaults to 100 and accepts 1..10000.

### Read-Only

- `entries` (Attributes List) Stored snapshots, oldest first among the newest `max_entries` entries. (see [below for nested schema](#nestedatt--entries))
- `id` (String) Data source identifier.

### Nested Schema for `entries`

Read-Only:

- `create_time` (String) When the server saved the snapshot, in RFC 3339.
- `data` (String, Sensitive) Snapshot rendered as config directives with secret-like values redacted.
- `data_redacted` (Boolean) Whether the server redacted secret-like values in `data`.
- `restore_id` (String) Identifier to pass to `rustfs_config_restore`.
