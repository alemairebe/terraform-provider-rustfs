# rustfs_integrity_inventory Data Source

One page of a bucket's per-object shard-integrity inventory (GET /rustfs/admin/v3/integrity/{bucket}/inventory).

The route lists object versions and reads each version's metadata; it does not read object payloads. A page holds at most 100 versions, so a large bucket needs the returned `next_key_marker` and `next_version_marker` to page through it. The checksums shown here are inventory evidence, not a migration acceptance decision: a `rustfs_integrity_job` compares against them only when the item supplies an independent `expected_sha256`.

## Example Usage

```terraform
# One page of a bucket's integrity inventory. Use the markers to page through a
# large bucket; RustFS returns at most 100 versions per page.
data "rustfs_integrity_inventory" "reports" {
  bucket = "logs"
  prefix = "reports/"
  limit  = 100
}

output "integrity_inventory_items" {
  value = data.rustfs_integrity_inventory.reports.items
}

output "integrity_inventory_next_page" {
  value = data.rustfs_integrity_inventory.reports.is_truncated ? {
    key_marker     = data.rustfs_integrity_inventory.reports.next_key_marker
    version_marker = data.rustfs_integrity_inventory.reports.next_version_marker
  } : null
}
```

## Schema

### Required

- `bucket` (String) Bucket whose inventory is read.

### Optional

- `key_marker` (String) Key marker from a previous page's `next_key_marker`.
- `limit` (Number) Maximum versions in the page. RustFS accepts 1 to 100; the default is 100.
- `prefix` (String) Object key prefix to narrow the page. The empty default covers the whole bucket.
- `version_marker` (String) Version marker from a previous page's `next_version_marker`. It requires `key_marker`; the server rejects a version marker on its own.

### Read-Only

- `bucket_incarnation` (String) Incarnation UUID of the bucket the page was read against.
- `id` (String) Data source identifier, derived from the bucket.
- `is_truncated` (Boolean) Whether more versions follow this page.
- `items` (Attributes List) Object versions in the page. (see [below for nested schema](#nestedatt--items))
- `next_key_marker` (String) Key marker for the next page, when `is_truncated` is true.
- `next_version_marker` (String) Version marker for the next page, when `is_truncated` is true.
- `observed_at` (String) Server time at which the inventory page was produced.

### Nested Schema for `items`

Read-Only:

- `audit_unsupported` (String) Why the version cannot be audited, for example `delete_marker`, `transitioned_object`, `transformed_object`, `multipart_object` or `invalid_protection_declaration`.
- `checksum_is_multipart` (Boolean) Whether the recorded checksum is multipart.
- `checksums` (Map of String) Checksums recorded for the version, grouped by algorithm.
- `data_dir` (String) Data directory UUID, when the version has one.
- `key` (String) Object key.
- `observation_error` (String) Why the version's metadata could not be observed.
- `protection` (String) Shard-integrity protection: `unknown`, `legacy`, `independent_commitment`, `invalid_declaration` or `no_payload`.
- `size` (Number) Object size in bytes.
- `source_fingerprint` (String) Fingerprint of the version's metadata.
- `version_id` (String) S3 version selector, including the literal `null` for the null version slot.
