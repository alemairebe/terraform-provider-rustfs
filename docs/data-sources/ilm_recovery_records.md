# rustfs_ilm_recovery_records Data Source

Reads the durable ILM recovery controls the server keeps for interrupted transitions and tier deletions. Recovery controls are the server's own repair queue, not Terraform state: this data source is read-only and never retries, abandons or exports a record.

## Example Usage

```terraform
data "rustfs_ilm_recovery_records" "failed_transitions" {
  protocol = "transition_transaction"
}

output "recovery_controls" {
  value = data.rustfs_ilm_recovery_records.failed_transitions.records
}

# Recovery controls the server has not finished retrying:
#
# data "rustfs_ilm_recovery_records" "retrying" {
#   protocol       = "transition_transaction"
#   classification = "retrying"
# }
```

## Schema

### Required

- `protocol` (String) Recovery protocol to list. The server requires it: `transition_transaction`, `tier_delete_journal` or `tier_delete_manifest`.

### Optional

- `classification` (String) Only return records with this classification: `retrying`, `retained_ambiguous`, `corrupt`, `operator_required`, `abandoned` or `terminal`.
- `limit` (Number) Maximum records to return in this page. The server defaults to 100 and accepts 1..1000.
- `marker` (String) Pagination marker returned as `next_marker` by a previous read. Leave unset for the first page.

### Read-Only

- `id` (String) Data source identifier, derived from the query.
- `incomplete` (Boolean) Whether the fleet could not be inventoried in full, so the page may be incomplete.
- `json` (String) Raw JSON response as returned by the RustFS admin API.
- `next_marker` (String) Marker for the next page; null when this page is the last one.
- `records` (Attributes List) Recovery controls in this page. (see [below for nested schema](#nestedatt--records))
- `truncated` (Boolean) Whether more records match than this page returned.
