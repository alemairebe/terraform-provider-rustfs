# rustfs_integrity_readiness Data Source

Shard-integrity readiness reported by GET /rustfs/admin/v3/integrity/readiness: whether protected writes are requested and activated on this node, whether the fleet operator attested to the rollout, and which requirements RustFS still considers unverified. A `migrate` integrity job only runs when `new_writes_enabled_here` is true, which needs both `RUSTFS_SHARD_INTEGRITY_WRITE` and `RUSTFS_SHARD_INTEGRITY_FLEET_CONFIRMED` on every node.

## Example Usage

```terraform
# Whether protected writes are activated on this node. A migrate integrity job
# needs new_writes_enabled_here, which requires RUSTFS_SHARD_INTEGRITY_WRITE and
# RUSTFS_SHARD_INTEGRITY_FLEET_CONFIRMED on every node.
data "rustfs_integrity_readiness" "current" {}

output "integrity_writes_enabled" {
  value = data.rustfs_integrity_readiness.current.new_writes_enabled_here
}

output "integrity_unverified_requirements" {
  value = data.rustfs_integrity_readiness.current.unverified_requirements
}
```

### Read-Only

- `fleet_capability_verified` (Boolean) Whether RustFS verified that the whole fleet can read and write the new format.
- `fleet_operator_attested` (Boolean) Whether the operator attested to the fleet rollout through `RUSTFS_SHARD_INTEGRITY_FLEET_CONFIRMED`.
- `id` (String) Data source identifier.
- `local_reader_supported` (Boolean) Whether this node can read shard-integrity metadata.
- `new_writes_enabled_here` (Boolean) Whether new writes get independent integrity commitments on this node. `migrate` integrity jobs need this to be true.
- `unverified_requirements` (List of String) Requirements RustFS still reports as unverified.
- `write_requested` (Boolean) Whether protected writes were requested through `RUSTFS_SHARD_INTEGRITY_WRITE`.
